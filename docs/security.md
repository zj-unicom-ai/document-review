# 安全说明

本文说明部署和使用 Document Review 时需要关注的安全边界。

## 部署安全

### 会话密钥

生产环境必须设置：

```env
AUTH_SECRET_KEY=<openssl rand -base64 48>
```

缺失时生产模式会拒绝启动。更换密钥会使现有登录会话失效。

### 默认超管密码

首次启动默认：

```text
租户：superadmin
账号：admin
初始密码：Changeme@2026
```

该值只用于激活空密码账号。公开部署后必须立即修改。后续容器重启不会覆盖已
修改密码。

### 网络暴露

建议：

- Web 仅通过反向代理暴露；
- API 与 Web 使用 HTTPS；
- MySQL 和 Redis 不直接暴露到公网；Compose 默认仅将 MySQL 发布到宿主机
  `127.0.0.1`，确需局域网访问时再显式修改 `MYSQL_BIND_HOST`；
- 仅开放必要端口；
- 为上传和审查接口配置合理的反向代理 body size 限制。

### 当前安全边界

- 平台未内置登录限速、账号锁定或验证码；不可信网络访问必须由反向代理或网关
  承担相应防护。
- OpenAPI `/docs` 与 `/redoc` 默认开启；公开环境应按需限制访问。
- 生产暴露建议由反向代理统一提供 HTTPS、访问日志、限速和 body size 限制。
- 外部资源适配器仍在建设中；相关规则应配置明确的错误处理策略，避免把外部
  系统异常误判为合规。

## 数据安全

### 上传文档

上传 PDF、解析 artifact 和批注 PDF 保存在 `STORAGE_ROOT`。这些文件可能包含
敏感业务内容，必须：

- 限制主机访问权限；
- 纳入备份；
- 不复制到公开位置；
- 定期按保留策略清理。

### LLM 数据流出

启用真实 LLM 后，平台会把受限文档上下文发送到配置的模型服务。部署前必须确认：

- 模型服务的数据处理政策；
- 是否允许处理上传文档；
- 网络链路是否加密；
- 是否需要自托管模型；
- trace 中保存的输入输出是否满足组织策略。

可私有化部署是本平台的安全目标之一，但真实外部模型的数据边界由部署者负责。

### 数据库与备份

数据库包含租户、用户、规则、审查记录和 trace。备份文件同样敏感，必须存放在
受限目录并加密保护。恢复流程见 [运维手册](operations.md)。

## 认证与权限

- 登录使用 HttpOnly Cookie；
- 权限按角色和菜单控制；
- 平台超管管理租户；
- 租户管理员管理本租户用户；
- 普通用户只能访问授权菜单；
- 所有业务数据读取带租户过滤；
- 平台级行对租户 API 只读。

## 外部资源

外部资源通过显式配置访问。不要把明文密码写入数据库或公开文档。推荐使用环境
变量、.secret 文件或部署平台 secret manager。

## 日志与 trace

日志和 trace 不应包含：

- API key；
- 数据库密码；
- 完整连接串；
- 私钥；
- 未脱敏的凭据。

审查 trace 会保存模型输入输出摘要，访问权限应与审查记录一致。

## 漏洞报告

请阅读 [Security Policy](../SECURITY.md)，不要在公开 issue 中提交漏洞细节、
上传样例或密钥。
