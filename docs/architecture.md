# 架构概览

Document Review 采用分层架构，平台代码负责机制能力，租户数据表达业务规则。
本文描述公开版本的模块边界、审查链路与扩展原则。

## 总体拓扑

```text
Web (React + Nginx)
  └─ /api
     └─ FastAPI
         ├─ MySQL：租户、用户、规则、审查记录与 trace
         ├─ Redis：公共基础设施依赖
         ├─ Storage Volume：上传 PDF、解析 artifact、批注 PDF
         ├─ MinerU-compatible API：PDF 解析
         └─ OpenAI-compatible LLM API：画像发现与理解类规则
```

## 后端分层

| 层 | 职责 |
| --- | --- |
| `app/api/` | HTTP 参数绑定、依赖注入、异常到响应映射 |
| `app/services/` | 用例编排、领域规则、多租户过滤与引用保护 |
| `app/models/` | SQLAlchemy 表模型 |
| `app/schemas/` | Pydantic API 契约 |
| `app/operators/` | 通用检查能力实现 |
| `app/engine/` | 文档上下文、画像、规则计划、执行与汇总 |
| `app/integrations/` | 外部系统适配 |
| `deploy/` | 容器入口与 mock 服务 |

核心无状态取证与审核能力位于 `packages/core/`，平台通过显式注入配置和模型服务
复用该能力。核心包不导入平台数据库、Web 配置或租户上下文。

## 核心领域对象

### 租户

租户是业务数据隔离边界。平台保留 `superadmin` 租户用于平台管理；业务租户由
平台超管创建。普通租户用户只能访问所属租户数据。

### 概念

概念表示文档中的语义检查对象，例如章节、表格、字段、图片组或结构化条目列表。
概念由租户自行定义，可以配置名称、别名、说明和数据形态。

### 规则

规则由锚点、检查能力、参数和违规输出模板组成。规则保存前会校验：

- 锚点概念是否可见；
- 检查能力是否存在；
- 参数是否符合能力 Schema；
- 数据形态是否匹配；
- 模型档位配置是否合法。

### 规则集

规则集将一组规则组织为一次审查的计划，可配置执行顺序、启停和参数覆盖。
上传审查时必须选择一个规则集。

### 审查运行

审查运行记录上传文件、解析状态、画像、规则计划、执行结果、违规汇总、trace 和
批注 PDF 路径。

## 审查执行链路

```text
上传 PDF
  → 文件校验与租户存储
  → MinerU artifact 生成 / 复用
  → DocumentContext 构建
  → 概念画像与证据定位
  → 规则集计划加载
  → 规则并行执行
  → 违规汇总与状态判定
  → 批注 PDF 生成
  → 审查结果与 trace 查询
```

规则编排、计划加载和结果判定是确定性代码。LLM 只用于画像发现、理解类规则或
可选摘要检查，并必须通过结构化输出与代码二次校验。

## 通用检查能力

平台检查能力按“锁定与提取”设计，具体业务判断由规则描述和参数表达。能力目录
通过 seed 登记到数据库，前端根据参数 Schema 动态渲染表单。

这种边界的意义是：

- 平台不内置行业结论；
- 新的检查口径优先通过租户规则配置；
- 能力接口保持可测试、可审计；
- 违规输出契约保持稳定。

## 多租户与权限

所有业务读写都经过租户过滤。平台级行对租户 API 只读，写入、修改和删除会返回
不可变错误。菜单权限由角色控制，平台超管可以管理租户，租户管理员可以管理本
租户用户与角色。

## 可观测性

每次审查保存：

- 计划内每条规则的执行状态；
- LLM 请求与结构化响应的安全 trace；
- 工具调用与耗时；
- 违规分类与严重程度汇总；
- 审查整体状态和错误信息。

## 扩展原则

新增外部系统时应在 `app/integrations/` 建立显式适配器，不把 SDK 调用散落在
服务层或算子中。新增检查能力时应同时交付：

- 参数 Schema；
- 结果语义；
- 单元测试；
- 前端文案；
- 能力目录 seed；
- 异常路径测试。
